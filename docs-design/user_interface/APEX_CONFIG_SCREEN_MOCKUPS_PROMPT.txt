STRICT MODE ADDENDUM (MANDATORY)

The following rules are mandatory for the new apex_config implementation:

1) No inline CSS in new files
- Do not add <style> blocks in apex_config_screen_mockups.html.
- Do not add style="..." attributes for presentation in new markup.
- All new styling must be in apex_config_screen_mockups.css.

2) No inline event handlers in new files
- Do not use onclick, oninput, onchange, onkeyup, or similar inline attributes in new markup.
- Bind events exclusively in apex_config_screen_mockups.js using addEventListener.

3) Separation of concerns
- Template contains structure and semantic attributes only.
- CSS contains visual concerns only.
- JS contains behavior and state transitions only.

4) Deterministic selector contract
- Every interactive element must have a stable id or data-action attribute.
- Use data-action and data-screen attributes for delegated event handling where practical.

5) Quality gates before completion
- Count check in new template must report:
  - onclick=0
  - oninput=0
  - style=0 (no presentational inline styles allowed)
- Validate that screen navigation graph works for all required flows.
- Validate that VALIDATION_PREVIEW_GATE (trace: Screen 6) displays consolidated validation and reference integrity results.

6) Compatibility guardrails
- Keep compatibility with existing /playground CSS utility assumptions and Bootstrap behavior.
- Do not alter existing apex_playground.html behavior while introducing /apex_config routes.

7) Delivery proof
