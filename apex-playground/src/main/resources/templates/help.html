Getting Started

Get up and running with APEX in 3 simple steps!

1
Add Your Source Data

Paste JSON, XML, or CSV data in the Source Data panel (top right). This is the data you want to validate or enrich.

2
Write Your YAML Rules

Define validation rules and enrichments in the YAML Rules panel (top left). Start with the basic template below.

3
Click Process

Hit the green Process button to run your rules. Results appear in the bottom panels.

Pro Tip: Click "Load Example" to see working examples you can modify and learn from.
YAML Basics

Every APEX configuration starts with a metadata section:

metadata:
  id: "my-config"
  name: "My First Configuration"
  type: "rule-config"
  version: "1.0.0"
  description: "A simple validation example"
  author: "Your Name"

rules:
  - id: "rule-1"
    condition: "#amount > 0"
    message: "Amount must be positive"
    severity: "ERROR"
Configuration Types
rule-config

For validation rules that check data conditions

enrichment

For adding or transforming data fields

rule-group

For grouping rules with AND/OR logic

data-source

For external data lookups (DB, REST, files)

Important: YAML is indentation-sensitive. Use spaces (not tabs) and be consistent with 2-space indentation.
Writing Rules

Rules validate your data using conditions written in SpEL (Spring Expression Language).

Basic Rule Structure
rules:
  - id: "validate-email"
    condition: "#email != null and #email.contains('@')"
    message: "Valid email address is required"
    severity: "ERROR"
    enabled: true
    tags:
      - "validation"
      - "contact"
Rule Keywords

id (required) condition (required) message severity enabled priority tags category

Severity Levels
ERRORCritical - must be fixed before processing
WARNINGImportant - should be reviewed
INFOInformational - good to know
Common Rule Examples
Required Field
#customerId != null
Numeric Range
#amount >= 0 and #amount <= 1000000
String Pattern
#code.matches('[A-Z]{3}')
List Contains
{'USD','EUR','GBP'}.contains(#currency)
More Rule Examples
# Date validation
- id: "future-date"
  condition: "#tradeDate != null"
  message: "Trade date is required"

# Cross-field validation
- id: "buy-sell-match"
  condition: "#buyAmount == #sellAmount"
  message: "Buy and sell amounts must match"

# Conditional validation
- id: "high-value-approval"
  condition: "#amount < 100000 or #approvedBy != null"
  message: "High value trades require approval"
Rule Groups

Rule groups combine multiple rules with logical operators (AND/OR) for complex validation scenarios.

Basic Rule Group
rule-groups:
  - id: "trade-validation-group"
    name: "Trade Validation"
    operator: "AND"
    rule-ids:
      - "validate-amount"
      - "validate-currency"
      - "validate-counterparty"
Operators
ANDAll rules must pass for the group to pass
ORAt least one rule must pass for the group to pass
Nested Rule Groups

Groups can reference other groups for complex logic:

rule-groups:
  - id: "basic-checks"
    operator: "AND"
    rule-ids:
      - "required-fields"
      - "valid-format"

  - id: "compliance-checks"
    operator: "AND"
    rule-ids:
      - "aml-check"
      - "sanctions-check"

  - id: "full-validation"
    operator: "AND"
    rule-group-references:
      - "basic-checks"
      - "compliance-checks"
Error Handling in Groups
rule-groups:
  - id: "resilient-validation"
    operator: "AND"
    error-handling: "continue-on-error"
    rule-ids:
      - "critical-check"
      - "optional-check"

Error handling options:

  • fail-fast - Stop on first error (default)
  • continue-on-error - Continue processing, collect all errors
  • skip-on-error - Skip failed rules, continue with others
Enrichments

Enrichments add, transform, or lookup data to enhance your records.

Enrichment Types
field-mapping

Copy or transform fields from source to target

lookup

Fetch data from external sources (DB, REST, files)

calculation

Compute new values using expressions

conditional-mapping

Map values based on conditions

Field Mapping Example
enrichments:
  - id: "copy-fields"
    type: "field-mapping"
    field-mappings:
      - source-field: "#currency"
        target-field: "base_currency"
      - source-field: "#amount * 100"
        target-field: "amount_cents"
Lookup Example
enrichments:
  - id: "get-customer-name"
    type: "lookup"
    lookup-config:
      data-source: "customer-db"
      lookup-key: "#customerId"
      result-field: "customerName"
      default-value: "Unknown"
Calculation Example
enrichments:
  - id: "calculate-total"
    type: "calculation"
    calculation-config:
      - expression: "#quantity * #unitPrice"
        target-field: "totalAmount"
      - expression: "#totalAmount * 0.2"
        target-field: "vatAmount"
Conditional Mapping Example
enrichments:
  - id: "map-status"
    type: "conditional-mapping"
    conditional-mappings:
      - condition: "#status == 'A'"
        target-field: "statusDescription"
        value: "Active"
      - condition: "#status == 'I'"
        target-field: "statusDescription"
        value: "Inactive"
      - condition: "true"
        target-field: "statusDescription"
        value: "Unknown"
Data Sources

Data sources define external systems for lookups and enrichments.

Data Source Types
Database

PostgreSQL, MySQL, Oracle, H2

REST API

HTTP/HTTPS endpoints

CSV File

Comma-separated value files

YAML Dataset

Inline or external YAML data

Database Data Source
data-sources:
  - id: "customer-db"
    type: "database"
    connection:
      driver: "org.postgresql.Driver"
      url: "jdbc:postgresql://localhost:5432/mydb"
      username: "user"
      password: "pass"
    queries:
      get-customer: "SELECT name, email FROM customers WHERE id = ?"
REST API Data Source
data-sources:
  - id: "pricing-api"
    type: "rest"
    connection:
      base-url: "https://api.example.com"
      timeout: 5000
    authentication:
      type: "bearer"
      token: "${API_TOKEN}"
    endpoints:
      get-price: "/prices/{symbol}"
Inline Dataset
data-sources:
  - id: "currency-codes"
    type: "inline"
    data:
      - code: "USD"
        name: "US Dollar"
        decimals: 2
      - code: "EUR"
        name: "Euro"
        decimals: 2
      - code: "JPY"
        name: "Japanese Yen"
        decimals: 0
External Data Source Reference

Keep configurations clean by referencing external data source files:

data-source-refs:
  - name: "customer-database"
    source: "data-sources/customer-db.yaml"
    enabled: true
  - name: "market-data"
    source: "data-sources/market-api.yaml"
    enabled: true
Best Practice: Use external data source references to separate infrastructure configuration from business logic.
SpEL Expressions

SpEL (Spring Expression Language) is used in conditions, calculations, and field mappings.

Field Access

Access fields using the # prefix:

# Simple field access
condition: "#amount > 1000"

# Nested field access
condition: "#trade.counterparty.name != null"

# Safe navigation (prevents null errors)
condition: "#trade?.counterparty?.name != null"
Operators
TypeOperatorsExample
Comparison== != < > <= >=#age >= 18
Logicaland or not !#a > 0 and #b > 0
Arithmetic+ - * / %#price * #qty
Ternary? :#status == 'A' ? 'Active' : 'Inactive'
String Methods
Contains
#email.contains('@')
Starts/Ends With
#code.startsWith('UK')
Length
#name.length() > 0
Regex Match
#phone.matches('[0-9]{10}')
Uppercase/Lowercase
#code.toUpperCase()
Substring
#code.substring(0, 3)
Collection Operations
# Check if value is in a list
condition: "{'USD','EUR','GBP'}.contains(#currency)"

# Array access
condition: "#items[0].price > 100"

# Collection size
condition: "#orders.size() > 0"
Safe Navigation: Use ?. to avoid null pointer errors: #customer?.address?.city

Complete Examples
Trade Validation Example

A complete configuration for validating financial trades:

metadata:
  id: "trade-validation"
  name: "Trade Validation Rules"
  type: "rule-config"
  version: "1.0.0"
  description: "Validates incoming trade data"
  author: "Trading Team"

rules:
  - id: "required-trade-id"
    condition: "#tradeId != null and #tradeId.length() > 0"
    message: "Trade ID is required"
    severity: "ERROR"

  - id: "valid-currency"
    condition: "{'USD','EUR','GBP','JPY','CHF'}.contains(#currency)"
    message: "Currency must be a valid ISO code"
    severity: "ERROR"

  - id: "positive-amount"
    condition: "#amount != null and #amount > 0"
    message: "Amount must be positive"
    severity: "ERROR"

  - id: "valid-counterparty"
    condition: "#counterparty != null and #counterparty.length() >= 3"
    message: "Valid counterparty is required"
    severity: "ERROR"

  - id: "high-value-warning"
    condition: "#amount < 1000000"
    message: "High value trade - requires additional review"
    severity: "WARNING"
Trade Enrichment Example

Enrich trade data with calculated fields and lookups:

metadata:
  id: "trade-enrichment"
  name: "Trade Enrichment"
  type: "enrichment"
  version: "1.0.0"

enrichments:
  - id: "add-timestamp"
    type: "calculation"
    calculation-config:
      - expression: "T(java.time.LocalDateTime).now().toString()"
        target-field: "processedAt"

  - id: "calculate-fees"
    type: "calculation"
    condition: "#amount != null"
    calculation-config:
      - expression: "#amount * 0.001"
        target-field: "brokerFee"
      - expression: "#amount * 0.0005"
        target-field: "exchangeFee"
      - expression: "#brokerFee + #exchangeFee"
        target-field: "totalFees"

  - id: "set-trade-status"
    type: "conditional-mapping"
    conditional-mappings:
      - condition: "#amount >= 1000000"
        target-field: "riskLevel"
        value: "HIGH"
      - condition: "#amount >= 100000"
        target-field: "riskLevel"
        value: "MEDIUM"
      - condition: "true"
        target-field: "riskLevel"
        value: "LOW"

Troubleshooting
Common Errors
"Invalid YAML syntax"

Usually caused by incorrect indentation or missing colons.

  • Use spaces, not tabs (2 spaces per level)
  • Ensure colons have a space after them: key: value
  • Check for missing quotes around strings with special characters
"SpEL evaluation failed"

The expression couldn't be evaluated against your data.

  • Check field names match exactly (case-sensitive)
  • Use #fieldName syntax to access fields
  • Use safe navigation ?. for potentially null fields
  • Verify the field exists in your source data
"Null pointer exception"

Trying to access a property of a null value.

  • Add null checks: #field != null and #field.length() > 0
  • Use safe navigation: #customer?.address?.city
  • Provide default values in enrichments
"Rule not executing"

Rule appears to be skipped.

  • Check enabled: true (or remove the enabled property)
  • Verify the condition syntax is correct
  • Check rule priority if using rule groups
YAML Syntax Tips
Wrong Correct
condition:#amount > 0 condition: "#amount > 0"
id: "rule-1" (tab) id: "rule-1" (spaces)
message: Error: bad data message: "Error: bad data"
fieldMappings: field-mappings:
SpEL Quick Fixes
Wrong Correct
amount > 0 #amount > 0
#data.amount #amount
#field == "value" #field == 'value'
#list.contains("X") {'X','Y'}.contains(#field)
Remember: APEX uses #fieldName to access fields directly, NOT #data.fieldName. This is a common mistake!
